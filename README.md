# Просмотр справки 1С

[<img src="docs/img/infostart.svg" alt="Infostart" height="24">](https://infostart.ru/public/2762838/)

Статья про эту обработку на Инфостарте: [Синтакс-помощник в режиме
предприятия](https://infostart.ru/public/2762838/) - как устроен пакет справки `.hbk`, замеры и разбор.

Внешняя обработка, которая открывает синтакс-помощник платформы прямо из
1С:Предприятия - дерево содержания, предметный указатель и текст статьи в обычном окне,
без конфигуратора.

Читает штатные пакеты справки `.hbk` из каталога установки платформы **средствами самой
1С**: ни внешних утилит, ни компонент, ни распаковки на диск. Формат контейнера
разбирается вручную, статья достаётся по смещению одной записи архива.

## Что умеет

- **Содержание** - дерево с ленивой подгрузкой: 28 360 разделов и статей, разворачивание
  узла за миллисекунду.
- **Индекс** - поиск по началу русского или английского имени, с владельцем через точку:
  `ТаблицаЗначений.Добавить (ValueTable.Add)`. Удачные запросы копятся в списке выбора.
- **Статья** - HTML как есть, со своим оформлением. Ссылки внутри справки открываются
  в том же окне, внешние уходят браузеру.
- **Навигация** - назад, вперёд, вышестоящий и нижестоящий раздел, «найти в содержании»
  (раскрывает дерево до открытой статьи).
- **Иконки** видов узлов - раздел, объект, метод, свойство, событие, статья.

Пакет открывается примерно за 1,4 секунды, статья показывается за 7 мс, повторно -
мгновенно. Память не раздувается: файл читается потоком, статьи достаются по одной.

## Установка

1. Скачать `hbk-viewer.epf` из [релизов](../../releases).
2. Открыть в 1С:Предприятии: **Файл → Открыть**.

Пакет справки обработка находит сама в каталоге установки платформы. Если нужен другой
файл - кнопка **Открыть** в командной панели.

Требуется платформа 8.3.14 или новее. Проверено на 8.3.27.

## Где читаются файлы

Работа с данными клиент-серверная, и **где читать - решается по доступности файла**:

| Где | Что происходит |
| --- | --- |
| Тонкий и толстый клиенты | читают сами: пакет лежит рядом, это их установка платформы |
| Клиент файл не видит | уходим на сервер: другая машина, другая ОС, сетевой каталог |
| Веб-клиент | файлов не видит вовсе - только сервер |

В веб-клиенте методы работы с файлами отказывают явным исключением с именем метода,
а не молчаливой заглушкой: так видно причину. Передачу файла на сервер обработка не
делает - это задача вызывающей стороны.

## Сборка из исходников

Нужна только установленная платформа 1С и Python 3. EDT не требуется.

```powershell
python tools\build_epf.py          # собрать dist\hbk-viewer.epf
python tools\build_check.py        # проверить форму целиком, ~25 секунд, кликов не нужно
```

Платформа ищется сама - самая свежая из установленных; переопределяется переменной
окружения `HBK_1C` (каталог `bin` или сам `1cv8.exe`). Рабочий каталог стендов -
`HBK_WORK`, по умолчанию временный каталог системы.

Если Python нет, обработку можно собрать одной командой конфигуратора из выгрузки,
которая лежит в репозитории:

```powershell
1cv8 DESIGNER /F<ИБ> /LoadExternalDataProcessorOrReportFromFiles ^
     dist\выгрузка\ПросмотрСправкиHBK.xml hbk-viewer.epf
```

## Как это устроено

```text
src/                исходники обработки
  form_ui.bsl         обработчики формы: дерево, индекс, статья, навигация
  engine_client.bsl   разбор оглавления и указателя, поиск, виды узлов
  engine_data.bsl     работа с файлами: поиск пакета, чтение статьи по смещению
  icons.bsl           иконки, собраны из src/icons/*.svg
  form_layout.xml     разметка формы в формате платформы
tools/              сборка и автономные стенды
dist/               собранная обработка и её выгрузка в файлы
docs/               формат .hbk, устройство обработки, стандарты кода
```

Модуль формы собирается из нескольких `.bsl`: движок один и тот же для обработки и для
стендов. Разметка формы правится в конфигураторе и возвращается в исходники скриптом
`import_form.py`.

Проверка формы автономная: та же форма кладётся общей формой в одноразовую тестовую
конфигурацию, проверяется `/CheckModules` для тонкого клиента, веб-клиента и сервера,
затем тонкий клиент со строгим режимом открывает её и прогоняет 36 самопроверок.
