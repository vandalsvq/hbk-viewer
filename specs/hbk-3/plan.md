# hbk-3: план реализации и решения

Транзиентный спутник [`spec.md`](spec.md).

## 1. План реализации

### Этап 1. Сопоставление с маской в движке

- `ЭтоМаска`, `СоответствуетМаске` в `engine_client.bsl`, область служебных
  процедур; `НайтиПоПрефиксу` → `НайтиПоЗапросу` с тремя рангами.
- Правятся вызовы в `form_ui.bsl`, `tools/form_check.bsl`, `tools/test_engine.bsl`.
- Gate: стенд `tools\run.py tools\test_engine.bsl …` показывает совпадения
  по `Струк*`, `*Струк*`, `Стр?ка` и время поиска.
- Оценка: ~90 строк вместе с комментариями (в issue было ~40 - без учёта
  быстрого пути по `СтрНайти` и рангов).

### Этап 2. Форма

- Подсказка поля поиска, сообщение о переполнении выдачи.
- Проверки масок в `tools/form_check.bsl`.
- Gate: `tools\build_check.py` зелёный.

### Риски и способы снижения

- **Скорость.** Наивное посимвольное сопоставление - 28 360 узлов × 2 имени ×
  длина имени вызовов `Сред`, это секунды, а не заявленные в issue 200 мс.
  Снижение: маска режется по `*` на сегменты, сегмент без `?` ищется одним
  `СтрНайти`; посимвольно сравниваются только сегменты с `?`. Замер на стенде
  до правки формы.
- **Регресс привычного поиска.** Запрос без масок обязан идти прежней веткой
  и давать прежнюю выдачу; проверяется тем же стендом.

## 2. Открытые вопросы

- Нужно ли подсвечивать в выдаче, какая часть имени совпала? Пока нет:
  выдача - плоский список представлений, подсветка потребует иного элемента.

## 3. Решения

| Дата | Решение | Причина |
| --- | --- | --- |
| 2026-08-13 | Запрос без масок ищет по началу имени, а не как `запрос*` | Привычно, совпадает с конфигуратором, не ломает мышечную память |
| 2026-08-13 | `НайтиПоПрефиксу` переименована в `НайтиПоЗапросу` | Имя перестало отражать суть; метод клиентский, внешних потребителей нет |
| 2026-08-13 | Своё сопоставление вместо `РегулярноеВыражение` | Объект появился в 8.3.23, минимум проекта - 8.3.14 |
| 2026-08-13 | Сегменты между `*` ищутся через `СтрНайти`, посимвольно - только при `?` | Посимвольный проход по 28 360 узлам стоит секунды |
| 2026-08-13 | Ранг 0 сравнивает имя с сырым текстом запроса | Статьи вида `?` и `*` (операторы языка) остаются находимыми |
| 2026-08-13 | Экранирования спецсимволов нет | В именах справки они встречаются только как целое имя, что закрыто рангом 0 |
| 2026-08-13 | Задача на паузе до переезда в EDT (hbk-6) | Иначе ~90 строк нового кода пишутся дважды: сначала как есть, потом под строгую типизацию |
