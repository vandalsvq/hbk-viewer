# hbk-3: Маски в указателе

> Ссылка на issue: `https://github.com/vandalsvq/hbk-viewer/issues/3`

## 1. Контекст и проблема

Вкладка «Индекс» ищет только по началу имени: `НайтиПоПрефиксу` сравнивает
запрос с `ИмяРу` и `ИмяEn` через `СтрНачинаетсяС`. Когда помнишь середину
имени, а не начало (`ТаблицаЗначений` против `Значений`), указатель
бесполезен - приходится листать дерево.

Конфигуратор в такой ситуации понимает маски, и это заметно удобнее.
Повторяем три знакомых по конфигуратору случая:

- `Струк*` - начинается с;
- `*Струк*` - содержит;
- `Стр?к` - один любой символ на месте `?`.

Работа идёт по уже загруженному оглавлению, файлов не касается.

Смежное: полнотекстовый поиск по статьям - отдельная задача
`https://github.com/vandalsvq/hbk-viewer/issues/2`, эта спека его не трогает.

## 3. Поведение

### 3.1. Основной сценарий

1. Пользователь набирает запрос в поле поиска на вкладке «Индекс».
2. Запрос без символов `*` и `?` работает как сейчас - **поиск по началу
   имени**. Поведение не меняется ни в чём, включая порядок выдачи.
3. Запрос с `*` или `?` считается маской и сопоставляется с именем **целиком**:
   - `*` - любое количество любых символов, включая ноль;
   - `?` - ровно один любой символ;
   - остальные символы сравниваются буквально.
4. Имя считается совпавшим, если под запрос подошло русское **или**
   английское имя узла. Регистр не учитывается.
5. Совпадения показываются в том же списке и так же сортируются по алфавиту.

### 3.2. Порядок отсечения выдачи

Выдача ограничена 300 совпадениями, как и сейчас. Что попадёт в эти 300,
определяет ранг:

| Ранг | Условие | Пример запроса и попадания |
| --- | --- | --- |
| 0 | имя точно равно тексту запроса | `Структура` → `Структура` |
| 1 | имя начинается с части запроса до первого `*` или `?` | `Струк*` → `СтруктураНастроек` |
| 2 | прочие совпадения с маской | `*Струк*` → `ТипыСтруктур` |

Ранг 0 сравнивает имя с **сырым текстом запроса**, поэтому статья, в имени
которой сам символ маски (`?`, `*`) - оператор условия, знак умножения -
находится по точному запросу.

Лимит применяется ко **всем** рангам, включая точные совпадения. Сейчас это не так:
`Максимум` ограничивает только «начинающихся», а точные добавляются без счёта, и на
частых именах (`Добавить`, `Записать`, `Прочитать`) выдача уходит за заявленный предел -
дефект №5 из [`../hbk-6/code-review.md`](../hbk-6/code-review.md).

Порядок внутри ранга 2 не определён: отсечение по лимиту при переполнении
выбирает произвольные совпадения. Это осознанное ограничение (см. 3.3).

### 3.3. Граничные случаи

- Пустой запрос или только пробелы - выдача пуста, как сейчас.
- Запрос `*` - совпадает со всем; выдача упрётся в лимит.
- Совпадений больше лимита - показываются первые 300 по рангу, состояние
  сообщает, что показаны не все, и предлагает уточнить запрос.
- Узлы, помеченные служебными, и узлы без пути в поиск не попадают - как сейчас.
- Экранирования спецсимволов нет: запрос `\*` ищет маску, а не звёздочку.
  Точное совпадение (ранг 0) закрывает практическую нужду.

### 3.4. Ошибки

Ошибочных состояний нет: любой запрос - валидная маска. Неудачный поиск -
пустая выдача и «Найдено: 0».

## 4. Контракты

### 4.1. Экспортные методы

`engine_client.bsl`, переименование `НайтиПоПрефиксу` → `НайтиПоЗапросу`:
имя перестаёт отражать суть, а метод клиентский и вне обработки не вызывается.

```bsl
// Ищет узлы по имени: по началу имени, а с символами * и ? - по маске.
//
// Параметры:
//  Пакет    - Структура - результат СобратьПакет.
//  Запрос   - Строка - что набрал пользователь; * и ? включают маску.
//  Максимум - Число - ограничение размера выдачи.
//
// Возвращаемое значение:
//  Массив из Структура - узлы оглавления, точные совпадения первыми.
//
Функция НайтиПоЗапросу(знач Пакет, знач Запрос, знач Максимум = 300)
```

```bsl
// Проверяет, подходит ли имя под маску с символами * и ?.
//
// Сравнение посимвольное только там, где в маске есть ?; остальное идёт
// через СтрНайти - на 28 360 узлах разница заметна.
//
// Параметры:
//  Имя   - Строка - имя узла в нижнем регистре.
//  Маска - Строка - маска в нижнем регистре.
//
// Возвращаемое значение:
//  Булево - Истина, если имя подходит под маску целиком.
//
Функция СоответствуетМаске(знач Имя, знач Маска)
```

```bsl
// Проверяет, есть ли в запросе символы маски.
//
// Параметры:
//  Запрос - Строка - что набрал пользователь.
//
// Возвращаемое значение:
//  Булево - Истина, если есть * или ?.
//
Функция ЭтоМаска(знач Запрос)
```

### 4.2. Имена узла в нижнем регистре

Узел получает два новых поля - `ИмяРуНРег` и `ИмяEnНРег`, заполняемые один раз при
разборе оглавления (`ЗаполнитьИмяУзла`). Поиск перестаёт вызывать `НРег`.

Сейчас каждый поиск считает `НРег` дважды на узел - около 57 тысяч преобразований
строк **на каждый введённый символ**, и это и есть замеренные 80 мс (дефект №6 из
[`../hbk-6/code-review.md`](../hbk-6/code-review.md)). Разовая плата уходит в уже
существующие 1,4 с загрузки, а сопоставление с маской становится почти бесплатным.

### 4.3. Изменения в форме

`ЗаполнитьСовпадения` вызывает `НайтиПоЗапросу`. Строка состояния при
переполнении: `Найдено: 300 (показаны не все, уточните запрос)`.
Подсказка поля поиска рассказывает про маски.

## 5. Критерии приёмки

- [ ] `Структура` находит `Структура` первой строкой - поведение прежнее
- [ ] `Струк*` даёт тот же состав, что и `Струк` без маски
- [ ] `*Струк*` находит `ТипыСтруктур` и другие имена с «струк» в середине
- [ ] `Стр?ка` находит `Строка`, но не находит `Строчка`
- [ ] `*` даёт непустую выдачу и сообщение о переполнении
- [ ] Поиск по английскому имени с маской работает так же, как по русскому
- [ ] Регистр запроса не влияет: `*СТРУК*` = `*струк*`
- [ ] Выдача не превышает лимит ни при каком запросе, включая частые точные имена
- [ ] Поиск не вызывает `НРег` - имена берутся из полей узла
- [ ] Поиск по маске на `shcntx_ru.hbk` укладывается в 300 мс (замер стенда)
- [ ] `tools\build_check.py` зелёный, включая компиляцию под веб-клиент

## 6. Вне области

- Операторы `И`, `ИЛИ`, `НЕ`, `РЯДОМ` из поиска конфигуратора
- Поиск по текстам статей (issue #2) и отбор по доступности
- Маски в дереве оглавления - только указатель
- Экранирование символов `*` и `?` в запросе
- Детерминированное отсечение при переполнении выдачи
